从 VS Code 到 AI 编程 Agent

适合谁？ 刚开始做 Python 项目、还不熟悉 VS Code 和命令行的同学。
需要多久？ 约 2--3 小时。
最终成果： 在 VS Code 中接入大语言模型，让 AI 不仅能回答问题，还能读取项目、修改代码、运行程序并协助修复错误。

🚀 先看路线：这次要完成什么？

不用先学完 VS Code，也不用先学命令行。

按照下面的顺序做即可：

安装 VS Code
    ↓
安装 Python + Python 扩展
    ↓
运行第一个 Python 程序
    ↓
安装 AI 编程插件
    ↓
接入 DeepSeek 等大语言模型
    ↓
先用 Chat 理解和修改代码
    ↓
再使用 Agent 操作项目
    ↓
让 Agent 运行 → 报错 → 修复 → 再运行
    ↓
用 Agent 辅助完成 Mini CourseShelf

完成本教程后，你应该能做到

  • 在 VS Code 中打开一个 Python 项目
  • 点击按钮运行 .py 文件
  • 在 VS Code 中和 AI 讨论当前代码
  • 让 AI 提出并执行文件修改
  • 看懂 AI 准备修改什么，而不是直接 Accept All
  • 让 Agent 运行程序并查看错误
  • 让 Agent 根据错误继续修复
  • 解释 LLM 和 Agent 的区别

1. 先搞清楚：我们到底在搭什么？

最终搭出的系统大致是：

┌──────────────────────────┐
│         VS Code          │
│   写代码 / 文件 / 运行     │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│      AI 编程插件          │
│  上下文 / 工具 / Agent    │
└────────────┬─────────────┘
             │ API
             ▼
┌──────────────────────────┐
│      DeepSeek 等 LLM      │
│   理解 / 推理 / 生成代码    │
└──────────────────────────┘

组件 可以理解成 做什么

VS Code 工作台 管理文件、编辑代码、运行程序

LLM 大脑 理解任务、分析代码、生成内容

AI 编程插件 连接器 + 工具箱 把项目交给模型，并提供文件、终端等工具

Coding Agent 能行动的 AI 助手 观察项目、决定下一步、调用工具、检查结果

最重要的一句话：LLM ≠ Agent。

DeepSeek 等模型负责"思考和生成"；IDE 插件把项目上下文和工具提供给模型。模型能够反复使用这些工具完成任务时，我们才得到一个 Coding Agent。

2. 安装 VS Code 和 Python

Step 1：安装 VS Code

打开：

https://code.visualstudio.com/

下载与你电脑系统对应的版本并安装。

第一次打开时，不用研究所有菜单。先认识四个地方：

  • Explorer：左侧，查看项目文件
  • Editor：中间，写代码
  • Extensions：左侧，安装插件
  • Terminal：底部，程序运行和命令执行的位置

💡 现在不会命令行完全没关系。
本教程尽量先用 VS Code 的按钮完成操作。后面 Agent 如果需要运行命令，我们再逐渐学习。

Step 2：安装 Python

打开：

https://www.python.org/downloads/

安装一个当前仍受支持的 Python 3 版本。

安装完成后，重新打开 VS Code。

Step 3：安装 Python 扩展

在 VS Code 左侧点击：

Extensions → 搜索 Python

安装 Microsoft 发布的 Python 扩展。

参考：

https://code.visualstudio.com/docs/python/python-quick-start

3. 先运行一个普通 Python 程序

Step 1：创建项目

在电脑上建立文件夹：

my-first-agent

然后在 VS Code：

File → Open Folder... → 选择 my-first-agent

Step 2：创建 hello.py

在左侧 Explorer 点击 New File：

hello.py

输入：

name = input("What's your name? ")
print("Hello,", name)

保存。

Step 3：运行

打开 hello.py，点击编辑器右上角：

▶ Run Python File

底部应该出现类似：

What's your name? Alex
Hello, Alex

✅ 检查点 1

如果你已经看到 Hello, Alex，说明：

VS Code → Python → 程序运行

这一段已经正常工作。

你可能注意到 Terminal 自动出现了一条命令。现在不需要背它。
Run 按钮其实是在替你调用 Python。

4. 给 VS Code 装上 AI

推荐方案：Continue + DeepSeek

本教程用 Continue 举例，因为它可以作为 VS Code 插件使用，并支持连接不同模型和 Agent 工作方式。

插件更新很快。按钮位置、模型列表或配置界面可能与本文略有不同。遇到差异时，以插件当前界面和官方文档为准。

Step 1：安装 Continue

在 VS Code：

Extensions → 搜索 Continue → Install

主页：

https://www.continue.dev/

文档：

https://docs.continue.dev/

安装后打开 Continue 面板。

5. 接入 DeepSeek

Step 1：准备 API Key

打开 DeepSeek API 文档：

https://api-docs.deepseek.com/zh-cn/

根据当前平台页面创建自己的 API Key。

它通常看起来类似：

sk-xxxxxxxxxxxxxxxx

🔐 API Key 不是普通配置文字

把它当成密码。

不要：

  • 写进 README.md
  • 上传到 GitHub
  • 发到群里
  • 截图公开
  • 直接写进 Python 源代码

如果 Key 意外公开，应立即在平台中撤销并重新创建。

Step 2：在插件中配置模型

不同版本界面可能变化，但你需要寻找类似：

Provider
Model
API Key

它们分别表示：

Provider → 去哪家模型服务商调用
Model    → 调哪个模型
API Key  → 你是否有调用权限

如果插件直接提供 DeepSeek，按照当前界面选择 DeepSeek 并填写 Key。

如果需要兼容接口，请以：

  • Continue 当前模型配置文档
  • DeepSeek 当前 API 文档

为准。

⚠️ 不要照抄几个月前教程中的模型 ID。
模型名称和接口会更新，请使用实验当天插件与 DeepSeek 文档中实际可用的名称。

6. 先不要用 Agent：第一次和代码聊天

打开刚才的 hello.py。

在 AI Chat 输入：

我是刚开始学习 Python 的大学生。

请逐行解释当前 hello.py。
不要修改代码。

重点解释：
1. input() 做什么；
2. name 是什么；
3. print() 为什么可以输出 name。

✅ 检查点 2

如果 AI 能根据 hello.py 的内容解释代码，说明：

VS Code
   ↓
AI 插件
   ↓
DeepSeek

基本已经连通。

7. 第一次让 AI 改代码

输入：

请修改 hello.py：

1. 除了姓名，再询问用户年龄；
2. 最后输出姓名和年龄；
3. 保持代码简单，适合 Python 初学者。

修改之前先告诉我你准备改什么。

这一次，不要习惯性点击 Accept All。

先看：

  • AI 准备改哪个文件？
  • 删除了什么？
  • 添加了什么？
  • 修改后的 Python 你能大致读懂吗？

推荐形成这个习惯：

提出任务
   ↓
看 AI 的计划
   ↓
检查修改
   ↓
运行
   ↓
观察结果
   ↓
决定下一步

而不是：

AI 写代码 → Accept All → 完成 ❌

8. 从 AI Chat 升级到 Coding Agent

普通 Chat 通常是：

你提出问题
    ↓
模型回答

Agent 则可以进一步获得工具，例如：

读取文件
搜索代码
修改文件
运行命令
读取运行结果

于是工作流程变成：

任务
 ↓
查看项目
 ↓
分析下一步
 ↓
调用工具
 ↓
观察结果
 ↓
继续分析
 ↓
再次调用工具
 ↓
完成 / 请求人类决定

这就是 Agent 最值得观察的地方。

9. 核心实验：让 Agent 自己发现并修 Bug

把 hello.py 暂时改成：

age = input("Age: ")

if age > 18:
    print("Adult")

运行。

程序会出现错误。

先不要自己修。

把任务交给 Agent：

请检查并运行当前程序。

如果出现错误：

1. 先解释为什么出错；
2. 告诉我准备修改哪一行；
3. 再修改代码；
4. 修改后重新运行验证；
5. 最后用适合 Python 初学者的语言总结这个错误。

如果需要执行终端命令，先告诉我这个命令是做什么的。

现在重点不是看 AI 最终写出了什么代码，而是观察它的过程：

读取代码
   ↓
运行
   ↓
看到错误
   ↓
分析
   ↓
修改
   ↓
再次运行

✅ 检查点 3

如果 Agent 能够根据实际运行结果继续行动，你已经体验到了最基本的 Agent Loop。

10. Agent Loop 到底是什么？

可以把它简化成：

┌─────────────┐
│   Observe   │
│    观察      │
└──────┬──────┘
       ↓
┌─────────────┐
│   Reason    │
│    分析      │
└──────┬──────┘
       ↓
┌─────────────┐
│     Act     │
│    行动      │
└──────┬──────┘
       │
       └──────────→ 再次 Observe

在编程中：

Agent 阶段 编程中的例子

Observe 读取 hello.py、查看报错 Reason 判断错误可能在哪里 Act 修改文件、运行程序 Observe again 查看新的运行结果

<details>

<summary>

<strong>{=html}展开：为什么网页里的 LLM 通常不等于 Coding Agent？</strong>{=html}

</summary>

如果你只在普通聊天框里输入：

帮我修复 hello.py

模型并不会自动拥有你电脑上的 hello.py。

Coding Agent 的关键在于 IDE 或 Agent 系统可以向模型提供工具。概念上类似：

read_file()
write_file()
search_code()
run_command()

例如：

你：“修复程序”
        ↓
LLM：“我需要先看文件”
        ↓
read_file("hello.py")
        ↓
LLM：分析代码
        ↓
write_file(...)
        ↓
run_command(...)
        ↓
LLM：检查结果
        ↓
决定是否继续

所以一个很实用的理解是：

Agent
≈ Model
+ Context
+ Tools
+ Loop
+ Human Control

</details>

11. Mini Project：用 Agent 辅助做 CourseShelf

现在不要继续做玩具代码。

建立一个真正的小项目：

CourseShelf/
│
├── main.py
├── courses.json
└── README.md

第一版只做：

  1. 添加课程
  2. 查看课程
  3. 删除课程
  4. 使用 JSON 保存数据

暂时不要加入：

  • Web 网站
  • 登录系统
  • 数据库
  • RAG
  • 向量数据库
  • LangChain
  • 多 Agent
  • 复杂 GUI

目标是学会和 Agent 一起开发，而不是让 AI 一次生成一个大系统。

12. 第一步一定是 Plan，不是 Coding

新建空的 CourseShelf 文件夹，在 VS Code 打开。

把下面这段直接交给 Agent：

我要做一个叫 CourseShelf 的 Python 小项目。

我是 Python 初学者。

第一版只需要：
1. 添加课程；
2. 查看课程；
3. 删除课程；
4. 使用 JSON 文件保存数据。

现在不要写代码。

请先：
1. 分析需求；
2. 建议需要哪些文件；
3. 把开发过程拆成不超过 5 步；
4. 每一步说明我要学到什么。

如果有需要我决定的问题，请先问我。

先检查它的计划

问自己：

  • 它有没有加入根本不需要的框架？
  • 这个方案我能理解吗？
  • 第一步是不是足够小？
  • 我完成一步后能不能马上运行验证？

13. 一次只实现一步

计划确认后：

现在只实现第 1 步。

要求：
1. 使用适合 Python 初学者理解的写法；
2. 不要提前实现后面的功能；
3. 修改前告诉我会创建或修改哪些文件；
4. 完成后解释关键代码；
5. 告诉我怎样运行和验证。

完成后，自己运行一次。

14. 让 Agent 测试，而不是只写代码

接着输入：

请检查刚才实现的功能。

先不要添加新功能。

请：
1. 运行程序；
2. 设计至少 3 个简单测试；
3. 如果发现错误，先解释原因；
4. 再修改；
5. 修改后重新测试；
6. 最后总结你实际修改了什么。

这里要特别观察：

Agent 真的运行并验证了吗，还是只说"应该可以工作"？

"代码看起来对"和"程序实际运行正确"不是一回事。

16. ⭐ 建议保存的 Agent Prompt

下面这个模板以后做项目也可以继续使用：

【我的背景】
我是 Python 初学者。

【任务】
请完成：__________

【工作方式】
1. 先阅读相关文件；
2. 先给出计划，不要马上修改；
3. 一次只完成一个小步骤；
4. 修改前说明准备改哪些文件；
5. 如果需要运行命令，先解释命令的作用；
6. 完成后实际运行或测试；
7. 如果出错，先解释错误原因，再修复；
8. 最后总结实际修改内容。

【限制】
不要为了完成任务引入不必要的框架或复杂技术。
优先使用我目前能够理解的简单实现。

17. 初学者使用 Agent 的 5 条规则

① 不要一上来就说"帮我把整个项目写完"

改成：

先分析需求，拆成不超过 5 步，不要写代码。

② 不要无脑 Accept All

至少看清：

改了哪个文件？
为什么改？
我能不能大致读懂？

③ 一次只做一个小功能

任务越小，越容易验证。

④ "Agent 说完成了"不等于完成

让它：

实际运行。

然后你自己再运行一次。

⑤ 看不懂终端命令时，不要假装看懂

直接告诉 Agent：

执行之前，请解释：
1. 这个命令做什么；
2. 每个重要参数是什么意思；
3. 它会不会修改我的文件。

这也是学习命令行的一种方式。
